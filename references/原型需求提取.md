# 从原型提取需求

用于本次输入包含前端代码、设计稿或截图的任务。

## 确定依据

- 按用户指定入口定位页面与相关组件，跟进事件处理、状态判断、条件渲染、权限判断和数据流。
- 界面可证明字段和操作入口，业务规则需结合事件逻辑、已有 PRD 或用户说明确认。演示数据、模拟接口、定时器动画、占位角色和静态成功提示不能直接推导为生产规则。
- 设计稿中可见的字段与交互标注可以引用，截图未显示的状态按本次实现需要记录待确认。用户明确要求覆盖整个新模块时，按该模块范围展开。
- 用户需求与原型不一致时，以用户当前明确要求为准。其他冲突需记录具体差异并询问，避免将所有资料拼接成更多功能。

## 按本次涉及的内容检查

| 涉及内容 | 重点提取 |
| --- | --- |
| 页面或弹窗 | 入口、触发条件、核心行为和提交结果，特殊退出行为及联动。 |
| 字段 | 名称、值来源、可选范围、必填、默认值及有依据的长度限制。 |
| 列表、筛选 | 查询范围、条件关系、排序、去重、批量操作对象与本次变化。 |
| 状态与任务 | 任务和条目的状态、转移条件、部分成功、重试对象及数据保留规则。 |
| 权限与数据 | 谁可操作、数据范围、失败后的处理、删除或编辑对关联数据的影响。 |
| 跨模块流程 | 输入输出、执行方、同步时点、步骤间数据与校验，按需引用已有逻辑。 |

这是查阅线索。将与本次变更有关且有依据的内容写入需求，其他项目跳过。必要但未明确的规则标待确认，避免填入猜测的数值、提示语或后台能力。

## 组织正文

按功能模块组织，用“功能项、描述、图例”等用户已有表格。同一逻辑连续表达，复杂条件用层级编号。行粒度跟随本次变更，可以是一项字段调整、一条处理规则或一个完整弹窗。功能描述写行为和结果，原型取证过程留在工作记录中。
